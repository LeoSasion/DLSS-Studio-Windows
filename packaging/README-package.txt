DLSS Studio — Windows x64 一键部署包

一、开始使用
1. 将 ZIP 完整解压到可写文件夹，例如 D:\Apps\DLSS Studio。
2. 双击“DLSS Studio.exe”，直接进入内嵌浏览器的独立工作台窗口。也可使用“启动工作台.bat”。
3. 窗口无系统边框，右上角可最小化、关闭；拖动顶部空白区域移动窗口，拖动外缘调整大小。
4. 上传图片或视频，选择增强参数，开始处理。

运行环境、Python 依赖、FFmpeg 和原始 DLSS 引擎均已内置；首次启动无需安装 Python、pip 或下载依赖。无需管理员权限。独立窗口使用 Microsoft WebView2：已安装时可直接运行；缺少时会询问是否安装包内的微软引导组件（仅首次安装此浏览器组件需要联网）。
请保留整个文件夹结构，不要单独移动 EXE，也不要直接从压缩包内运行。

二、独立窗口与浏览器
DLSS Studio.exe 是唯一启动入口。启动后，右上角点击“浏览器”可在默认浏览器中访问同一个服务。
默认地址为 http://127.0.0.1:7860/；端口占用时会自动选择可用端口，“浏览器”按钮会打开实际地址。
关闭独立窗口会停止服务；使用外部浏览器时，请保持独立窗口开启，也可以将它最小化。正在处理时关闭会询问是否中断。
上传素材和任务显示属于各自页面会话，浏览器与独立窗口不会同步当前预览，但共用处理服务及输出目录。
分辨率仅提供原始、720p、1080p、2K（1440p）、4K，保持素材比例；原始保留原尺寸。高级参数按可用空间自动展开，不足时使用分页面板。强度以百分比显示，鼠标停留可查看说明，恢复默认可重置高级参数。首次打开显示上传区。

三、系统与显卡
目标平台：Windows 10/11，64 位 x64。启动窗口使用 .NET Framework 4.6.2 或更高版本（现代 Windows 通常已内置）。
需要兼容原始 video2dlssnr / DLSS NR 的 NVIDIA 显卡和驱动。此包不安装或修改显卡驱动，也不会让不支持的显卡获得 DLSS NR 能力。
当前工作站已测试 RTX PRO 6000 Blackwell、591.86 驱动的图片和短视频神经渲染；其他硬件需实际验证。
视频显卡编码另有驱动要求，程序启动时检查可用性。不满足时默认使用 ProRes（CPU 编码），文件体积可能较大。

四、数据和外观
原始上传：app\uploads\
输出结果：app\ui_out\<任务编号>\
重启服务后需重新上传素材，已输出文件仍保留。此发布包不包含工作目录的历史上传、处理结果或日志。
深色与浅色主题可在网页右上角切换。已包含最终版样式：深色光泽折射边缘、浅色中性微渐变与阴影、透明预览背景和适配窗口的无滚动主界面。

独立窗口的主题与浏览器数据保存在 desktop-profile\；此目录不会打入发布包。

五、排查
启动失败：查看 logs\desktop-server.log，确认已经完整解压且目录可写。
处理失败：查看网页底部状态按钮中的任务日志。
显卡或编码不兼容：更新显卡驱动，或改用支持的 CPU 编码选项；CPU 编码仍需要兼容显卡进行 DLSS 神经渲染。

源代码：app\web 为前端，app\studio_server.py 为服务，launcher-source\StudioService.cs 为服务进程管理源码，launcher-source\DesktopShell.cs 为独立窗口源码。
第三方说明：licenses\。文件 SHA-256 清单：manifest.json。

## 自动显卡适配

统一使用 DLSS 5 神经渲染。旧 E/F/J/K/L/M 是内部 SR 预设，并非分别验证过的 DLSS 5 模型，现已移除；内部放大阶段保持驱动默认预设。

自动识别 RTX 30 / 40 / 50 系及可识别的同架构专业卡，通过 DXGI 高性能排序选择显卡，使用 CUDA LUID 核对架构，显式传入 DXGI 编号和对应 DLL 目录。每次提交任务前重新识别，避免多卡或热插拔造成编号混淆。运行时三套组件已内置，无需手动替换。未知显卡、缺失或校验失败的组件会显示原因，不会猜测其他架构 DLL。

三套 DLL 来自 [purkatyy/DLSS5- 的 dlss 发布](https://github.com/purkatyy/DLSS5-/releases/tag/dlss)。下载地址、附件及 DLL 的 SHA-256 记录在 `app/dlss5-components.json`；仅提取各包中的 `nvngx_dlssnr.dll`。它们不属于本项目的 MIT 授权范围，原有版权及适用条款继续有效。

已在 RTX PRO 6000 Blackwell 工作站使用 50 系 DLL 实测。30 / 40 系已有型号识别、显卡编号、组件匹配的自动化测试，尚未在实体卡上验证渲染。原发布者也注明 30 / 50 系替换包未经其测试。界面区分“已匹配”和本次启动“已成功渲染”。
